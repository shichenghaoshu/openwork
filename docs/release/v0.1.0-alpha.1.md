# OpenWork v0.1.0-alpha.1

`v0.1.0-alpha.1` is the Bootstrap Runtime Milestone release. It establishes a
native, cross-platform Rust foundation for discovering, diagnosing, planning,
installing, and recording externally managed agent runtimes without silently
modifying an existing installation.

## Included

- A seven-crate Rust workspace pinned to Rust 1.95.0 and a native `openwork` CLI.
- Stable platform detection, structured Doctor results, machine-readable error
  codes, redaction, and JSON schemas.
- A complete `AgentRuntime` contract, manifest registry, and compatibility suite.
- Claude Code and Codex adapters that point to their official upstream bootstrap
  sources instead of vendoring or redistributing provider software.
- One install plan for dry-run and execution, with explicit `--execute --yes`
  consent, executable-plus-argument command invocation, bounded output,
  cancellation, timeouts, rollback reporting, and existing-install protection.
- An HTTPS-only downloader with exact-host allowlisting, redirect checks, a
  64 MiB limit, streaming SHA-256, and no-clobber persistence.
- A versioned runtime lockfile with explicit checksum authority, source and
  license provenance, secret separation, cross-process locking, atomic
  replacement, migration boundaries, and Unix mode `0600`.
- Native compatibility jobs for macOS arm64/x64, Ubuntu arm64/x64, and Windows
  Server 2025 x64, plus verified release archives, checksums, build provenance,
  GitHub attestations, and an SPDX SBOM.
- Checksum-verifying POSIX and PowerShell installers that refuse replacement by
  default and restore a backup after a failed forced update.

The milestone was delivered through Issues #1, #2, #5, #10, #39, #40, #41,
#42, #43, #55, and #59 and implementation PRs #44 through #60.

## Verification

- `cargo fmt --all --check`
- `cargo clippy --workspace --all-targets --locked -- -D warnings`
- `cargo test --workspace --all-targets --locked`
- `cargo build --release --locked`
- JSON schema, documentation-link, shell syntax, PowerShell parser, license,
  secret-scan, SAST, SBOM, and native platform matrix checks.
- The local macOS arm64 host discovered a healthy, authenticated Claude Code
  installation. It also found a broken local Codex wrapper whose vendor binary
  is absent; OpenWork reported the condition and did not attempt repair.

## Known limitations

- Windows 11 client and WSL2 remain manual-validation targets. Windows Server
  native CI and Linux CI are recorded separately and are not presented as those
  environments.
- No real provider installation or provider task was run during release
  validation, because both would change user-controlled external state. Dry-run,
  isolated fake execution, rollback, and a directory-only integration install
  were exercised instead.
- The current Claude Code and Codex upstream bootstrap endpoints do not publish
  an adjacent checksum consumed by this milestone. OpenWork therefore records
  the observed download digest and its checksum authority, and requires explicit
  execution consent.
- The authenticated GitHub token does not have `project` or `read:project`
  scope, so the optional GitHub Project board cannot be created in this run.
  `.github/PROJECT_SETUP.md` and `scripts/bootstrap-github.sh` contain the exact
  continuation procedure.
- This alpha completes the prompt's Bootstrap Runtime Milestone. The broader
  OpenWork product stack and MinerU license review remain later-phase work.
